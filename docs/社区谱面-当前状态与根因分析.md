## 二、机制（本轮真正想通的一环）

```
Java:   c_path_base     = getFilesDir()          → /data/data/<pkg>/files
        c_path_install  = base + "/install/"      → files/install/
        c_path_external = base + "/external/"     → files/external/
        setBasePath(install, external) ─────────► 引擎

原生:   asset://X ──┐
        file://install/X ──┤─ 剥前缀 ─► 裸相对路径 X ─► sprintf("%s/%s", root, X)
        file://external/X ─┘                        （root 运行时由 JNI 设置）
```

**要点**：install/ 与 external/ 在引擎里是同一文件系统的两个逻辑视图，最终都拼到同一个 root。
客户端下载的资源（设备上 490MB 音乐、全部谱面缓存）都落在 `files/external/`，
所以 root 极可能就是 `files/external`。而 `files/external/db/` 目录不存在 →
`db/live/live.db_` 打不开 → 客户端拿不到社区曲数据。

**这解释了"数据全对但显示不变"**：我们改的是 `install/`（APK 释放位置）和资源包，
但客户端实际读 `external/`，那里从来没有 db。

## 三、修复（一条命令）

```bash
# 设备连接 + root 后执行
python honoka-chan-dev/tools/deploy_external_db.py
```

脚本做的事（含部署前后双重自检）：
1. **本地自检**：解密 db，逐一验证 24 首 track→setting→difficulty→谱面关联，不过则终止
2. `am force-stop` 游戏
3. 推送 `temp/idfix_live.db_` → `su cp` 到 `files/external/db/live/live.db_`
4. 同步一份到 `files/install/db/live/live.db_`（双保险）
5. 删除 `files/**/*.db`（无下划线的解密缓存）
6. **设备端 md5 校验**（被 MIUI 拒时降级为大小比对）

随后 `python honoka-chan-dev/tools/verify_community.py` 自动验收。

## 四、本轮其它已落地修复（都有效，勿回退）

1. **音频容器类型码**：音乐是 `0x26`，`tools/sif_crypt.py` 原来一律 `0x09` 导致客户端解不开→静音。已按扩展名修正，24 首社区音频重新加密，往返逐字节一致。
2. **资源包 CRC 损坏**：`4_0_477.zip`、`4_0_461.zip` 各有一个坏 texb，客户端反复重试同一包最终"通信中断"。已重建，全量扫描 9260 包 0 损坏。
3. **`pkg_size` 与实际不符**：23 个 `99_0_*` 差 6144B。已全量校正。
4. **`special_live_m` 混入 24 首社区曲**：点「特别」tab 必崩（客户端该表 0 条，nil 索引）。已删。
5. **`attachByAssets` bug**：`live_setting_m` 无 `live_difficulty_id` 列导致 `attached` 恒空。已改两段关联。
6. **社区曲 ID 重映射**：9001+/90001+/900001+ 客户端不认，已改官方区间空位（track 22/24/27…、setting 1156…、difficulty 31…），category=4(Liella)。
7. **熄屏假卡死**：MIUI 熄屏限网导致下载暂停。已用 `screen_off_timeout=2147483647` + `stay_on_while_plugged_in=7` 根治。
8. **`.redownload_pad` 隐藏条目**：为强制客户端重下而往 99_0_115.zip 加的填充条目会导致下载进度 NaN，已移除。

## 3. 与 v0.3 的四处偏差（都是实测后改的）

### 3.1 抽屉 → 「启动器 + 内置面板」两条腿

v0.3 想让所有操作都在游戏里的侧边抽屉完成。实测发现抽屉本身没问题（右边缘把手 + 长按 0.6 s 就能拉出），
但**服务端管理**（账号、卡池、道具、乐曲上下线、日志）放抽屉里体验很差：横屏、空间小、还要和打歌抢触点。

最终形态：

- **启动器（Flutter，Windows / Android）**：跑在另一块屏 / 另一台设备上，负责服务端生命周期 + 全部管理功能；
- **客户端内置 GM 面板**：只管打歌相关的即时开关（加金币/等级/爱心、自动打歌、轨道校准、偏移）。

两者通过 `/local/*` 接口共享同一份状态，改完即时生效。

### 3.2 回环地址 → 局域网直连（`adb reverse` 作为兜底）

v0.3 主张把地址钉死 `127.0.0.1` 以换取"AppAssets.zip 只打一次包"。实测取舍：

- 钉死回环意味着客户端必须走 `adb reverse` 或内嵌服务端，**无线场景直接不可用**；
- 而改包脚本已经做到**一条命令出包**（约 4 分钟），重打成本可以接受。

所以现在是：APK 里写死 `<PC 的局域网 IP>:8080`，换 IP 就重跑
`patch_client_lan.ps1 -Ip <新 IP>`。等形态 A（内嵌服务端）落地后，再回到回环方案。

### 3.3 账号：保留原生登录页，不做设备绑定

v0.3 5.3 的"device_binding + 密码校验后自动落号"没有实现。现在的做法：

- 客户端仍是原生盛趣登录页；服务端 `/v1/account/login` 手机号 + 密码，不存在即注册；
- 切换账号 = 启动器「账号」页改绑 / 客户端抽屉输入手机号密码（`POST /local/switch`）；
- **没有引入任何"隐式身份"**，密码始终是唯一凭据——比 v0.3 的方案更简单也更安全。

### 3.4 `extracted` 资源缺口：改成"缺失即跳过"，不补

v0.3 第 6 章要求补 `static/<os>/extracted/`（剧情等按路径拉取的资源）。本期结论：

> **不补，但保证不崩**——凡是查不到谱面 / 资源的曲目一律从可打列表里过滤掉（`hasBeatmap` 已在用），
> 客户端表现为"这首歌不在列表里"，而不是闪退或空进度条。

真要把剧情补齐，是独立工程量（见 12.4）。

## 7. 逆向成果（可复用资产，都在 `tools/`）

1. **客户端 Lua 全部可解密**：`honoka2.exe -b <同名文件> in out`（key 由文件名派生），1979 个 `.lua` 全部成功。
2. **SIF 字节码格式**（`tools/siflua.py`，已能解析 1600+ 文件）：
   - 12 字节 luac 5.1 头（版本字节改成 `0x52`）+ **5 字节 magic `19 93 0d 0a 1a`**
   - main chunk：`linedefined(4) lastlinedefined(4) nups npar isvararg maxstack`；**子函数少 `isvararg`**
   - debug 段：`n(4) + n×2 + 16`
   - **opcode 表被改过**：SIF 在索引 2 插了自定义宽 LOADK，`SIF_op ≥ 3 ⇒ std = SIF_op - 1`
     （验证：14507 个 proto 里 14506 个末指令 op=31 = RETURN）
3. **游戏文件加密**（`tools/honoka_encrypt.py`）：直接调 `honoka.dll` 的 v4 模式，容器头覆盖成官方值
   `?? ?? ?? ?? c2 09 00 02 00×8`，产出与官方文件**逐字节相同**，往返验证通过。
4. **判定窗口**（`tools/patch_settings_perfect.py`）：`m_live/settings.lua` 里
   `ACCURACY = { perfect = 16, great = 40, bad = 112, miss = 128 }`，单位是像素，
   `m_live/note.lua` 会按当前流速折算成时间（`ACCURACY_LIMIT_SPEED = 0.8`）。

## 8. 谱面是怎么加载的（回答 v0.3 末问 ①）

### 8.1 服务端侧（数据来源）

1. 曲目主数据在 `assets/main.db`：
   - `live_setting_m`（1894 行）：`live_setting_id / live_track_id / difficulty / stage_level /
     notes_setting_asset / lane_count / swing_flag / ac_flag / *` 评级线
   - `live_track_m`（366 行）：曲目 → 成员分组
2. 谱面本体在 `assets/serverdata/beatmaps/`：**1912 个 JSON**，文件名即 `notes_setting_asset`
   （如 `Live_0001.json`）。
3. 客户端请求 `/live/play`（及 `liveNext` / `preciseScore` 等）时，服务端：
   `live_setting_m.notes_setting_asset` → 读 `assets/serverdata/beatmaps/<asset>` →
   `loadLiveNotes()` → 塞进响应里的 **`notes_list`**（`internal/handler/live/live.go:58,98`）。
4. 可用性过滤：`hasBeatmap()` 检查文件是否存在，**不存在就不进可打列表**
   （`internal/handler/api/live/common.go:113`）。乐曲"上线/下线"就是把这个 JSON 在
   `beatmaps/` 与 `beatmaps_disabled/` 之间搬移（`admin_media.go:26`）。

### 8.2 谱面 JSON 的字段（一首歌的完整内容就是这个数组）

```json
[{"timing_sec":6.664,"notes_attribute":1,"notes_level":1,
  "effect":3,"effect_value":2.286,"position":5}, ...]
```

| 字段 | 含义 | 备注 |
|---|---|---|
| `timing_sec` | 判定时刻（秒，浮点） | 基准是歌曲音频起点，**不是谱面文件起点** |
| `position` | 轨道号 1..N | `lane_count` 5 或 9；1 在最左 |
| `effect` | 音符类型 | `1` 普通单点、`2` 长按、`3` 同时押（成对出现）、另有上滑/下滑类 |
| `effect_value` | 该 effect 的附加参数 | 实测 Live_0001 里普遍是 `2.0` / `2.286`，**不是长按时长**（长按时长由客户端按 effect 类型自算） |
| `notes_attribute` / `notes_level` | 音符属性/等级 | 影响图标与打击特效 |

### 8.3 客户端侧（渲染与判定）

```
/live/play 返回 notes_list
      ↓
m_live/model/notes.lua      Notes.initializeLane / prepareNotes / update   ← 组装
      ↓  NoteCache / NoteSimulator（note_cache.lua, note_simulator.lua）
m_live/note.lua             Note.new：按 timing 与当前流速算 spawn 时间、
                            用 settings.lua 的 9 轨角度表算轨道坐标
      ↓
判定：m_live/model/accuracy.lua  getTapAccuracy/getReleaseAccuracy
      ← 读 accuracy_tbl（= ACCURACY 阈值 ÷ 流速）
      ↓
m_live/model/notes.lua      countAccuracy / updateNoteLog / score
```

关键点：

- **客户端不校验谱面归属**，只按 `timing_sec` + `position` 生成音符 → 这意味着**换谱面不需要动客户端**；
- 轨道坐标是极坐标：`X=480, Y=160, R=400, CHARACTER_ANGLE=360/8`，5 轨角度
  `35 / 62.5 / 90 / 117.5 / 145`（间隔 27.5°）；9 轨几何在加密的 `ui_live.json` 二进制里；
- 判定阈值单位是**像素**（`16 perfect / 40 great / 112 bad / 128 miss`），除以流速再折算时间。

## 9. lllpractice 谱面能不能移植（回答 v0.3 末问 ②）

**能，而且不用改客户端。** 只要产出两个东西：

1. `assets/serverdata/beatmaps/<新文件名>.json`（就是 8.2 的数组）；
2. `live_setting_m` 里插一行，把 `notes_setting_asset` 指向它，并指定 `live_track_id`（歌曲音频）、
   `difficulty`、`lane_count`、评级线。

lllpractice 的谱面本质也是「(时间, 轨道) → 音符」序列，映射关系：

| lllpractice | SIF | 注意 |
|---|---|---|
| 时间（ms 或 beat） | `timing_sec = t/1000` | beat 制要按 BPM 表换算，且要加上**歌曲前奏偏移** |
| 轨道 index 0..8 | `position = index + 1` | lllpractice 多为 9 轨；5 轨谱要重映射到 1..5 |
| 单点 note | `effect = 1, effect_value = 2` | 基准值 |
| hold 头/尾 | `effect = 2`（成对） | ⚠️ 时长语义待定：实测 `effect_value` 恒为 ~2，长按时长由客户端自算，**移植时要实测确认尾巴怎么表达** |
| 同时押 | `effect = 3`（成对出现） | 两轨各一条，`effect_value` 同值 |
| 滑键 | SIF 有专门 effect（`effect` 4+） | 需要按官方谱反查编号，lllpractice 无对应概念，通常降级成单点 |

落地建议（低成本路线）：

1. 先做**离线转换脚本**：`lllpractice.json → notes_setting_asset.json`，输出到 `beatmaps/`；
2. 在 `live_setting_m` 里复制一首已有曲目的行，改 `live_setting_id`（新 id）与 `notes_setting_asset`；
3. 音频复用现有曲目即可（`live_track_id` 不变），这样最省事；
4. 启动器「乐曲」页已经有**谱面导入导出**（`admin_media.go`），把脚本挂在它后面就等于"一键导入"。

**风险**：`swing_flag`/`ac_flag`（打歌模式）、`lane_count` 必须和谱面一致，否则音符会跑出判定区；
超长谱（>1000 音符）没测过上限。

## 10. 原版谱面全启用 + 筛选（回答 v0.3 末问 ③）

**已经全启用了**：`beatmaps/` 下 1912 个谱面全部参与 `hasBeatmap` 判定，`live_setting_m` 1894 行
里只要有对应文件就进可打列表。所以"不能打的歌"只剩两类：文件缺失、以及被手动下线到
`beatmaps_disabled/` 的。

筛选的三个层次（按成本从低到高）：

| 层 | 做法 | 工作量 | 说明 |
|---|---|---|---|
| L1 白名单/黑名单 | 现有 `beatmaps` ↔ `beatmaps_disabled` 搬移 | ✅ 已实现 | 启动器「乐曲」页勾选即可，服务端下次列表请求就变 |
| L2 按条件查询 | `listAvailableLives` 加 `difficulty / star / group / keyword` 参数 | 0.5 人日 | 只改 SQL where + 返回，客户端列表自动跟着变（客户端不缓存全量） |
| L3 客户端内筛选 UI | 在客户端的选曲界面加筛选器 | 3~5 人日 | 要改客户端 Lua（我们现在有反编译 + 重加密能力，可行但不划算） |

**建议走 L2**：筛选逻辑放服务端，客户端零改动。若要"用户自己选想看到哪些曲目"，
在启动器里做成"分组/难度/星级"多选，落到 beatmap 目录即可。

## 11. 分发与运维

### 11.1 首次部署

1. 数据包解压到 `D:\LLSIFLocal\`（路径不含中文/空格）；
2. Release 的 Windows zip 解压到 `D:\LLSIFLocal\launcher\`；
3. 双击 `llsif_local_admin.exe` → 概览页点「修正 cdn_server 为本机 IP」；
4. 客户端 APK 按你的 IP 重打包后安装（`tools\patch_client_lan.ps1 -Ip <IP>`）；
5. 首次进游戏任意手机号 + 密码即注册。

### 11.2 升级

- 服务端：停服 → 换 `honoka-chan.exe` → 起服（`assets/*.db` 保留）；
- 启动器：覆盖 `launcher\` 目录；
- 客户端：同签名覆盖安装，不丢档。

### 11.3 备份

- 存档 = `assets\data.db`（1.9 MB）；
- 曲目/卡表 = `assets\main.db`（5.6 MB）；
- 启动器「工具」页可导出/恢复单账号备份；服务端启动目录 `assets\backups\` 留 4 份滚动备份。

### 11.4 校验

```powershell
cd D:\LLSIFLocal\deliver
Get-FileHash * -Algorithm SHA256
# 与 SHA256SUMS.txt 比对；数据包亦可 7z t 全量校验
```

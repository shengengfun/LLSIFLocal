# 无线局域网部署（摆脱 USB / adb）

> 目标：平板不插线、不跑 adb，只连同一个 WiFi 就能进游戏。

## 一、结论先看

客户端里有**两处**服务端地址，只改一处是没用的 —— 这也是之前「只能靠 adb reverse」的根因：

| 位置 | 内容 | 谁在用 |
|---|---|---|
| `classes.dex` → smali 常量 | `http://127.0.0.1:8080` | ghome SDK，打 `/v1/*`（握手、账号、登录） |
| `assets/AppAssets.zip` → `config/server_info.json` | `"domain": "http://192.168.1.123"` | 游戏本体，拼 `/main.php/*`（真正的游戏接口） |

第二个文件是 **SIF CN v4 加密**的，之前一直改不动，踩坑记录见下。

## 二、关键发现：honoka2 的版本号写在字母后面

```
honoka2 -c  ...   → 生成 CN **v3** 文件（客户端解不开 → 闪退）
honoka2 -c4 ...   → 生成 CN **v4** 文件（客户端正常）
```

字母后面的数字就是加密版本（源码 `map_letter_to_gamefile` 里 `letter[1]` 取 `'1'..'6'`）。
所以：

```powershell
# 解密
honoka2 -c4 -b server_info.json 加密文件 明文.json
# 加密
honoka2 -e -c4 -b server_info.json 明文.json 加密文件
```

用 `-c4` 加密后再解回来，内容完全一致（脚本里做了这个自检）。

> 这个坑的代价：用 `-c` 生成的文件头是 `30 54 47 0c 00 00 00 00`（v3），
> 正确文件是 `30 54 47 0c 00 00 00 02`（v4）—— 差一个字节，客户端直接闪退。

## 三、一键脚本

```powershell
cd d:\LLSIFLocal\honoka-chan-dev\tools
.\patch_client_lan.ps1 -Ip 192.168.0.106          # 生成 + 安装
.\patch_client_lan.ps1 -Ip 192.168.0.106 -NoInstall # 只生成 APK
```

脚本做的事：

1. `apktool d -r` 解出 smali（首次慢，之后复用 `temp\netpatch\decoded`）
2. 把所有 `http://127.0.0.1:8080` 与旧 LAN 地址统一改成 `http://<IP>:<端口>`
3. `apktool b` 重打包
4. 从新 APK 里取出 `AppAssets.zip`，用 `honoka2 -c4` 解密 `config/server_info.json` 与 `config/package_info.json`：
   - `server_info.json` 的 `domain` → `http://<IP>:<端口>`
   - **两个文件的 `server_version` 都改成 `-PackageVersion`（默认 97.4.6，必须等于服务端 `config.PackageVersion`）**
   - 改完 `-e -c4` 加密 → **往返自检**
5. 替换 `AppAssets.zip` 与 `assets/version` 里的 MD5
6. `zipalign` + `apksigner`（用 `askey.keystore`，与已安装版本同一证书，**不会丢游戏数据**）
7. `adb install -r`，并清掉 `adb reverse`

产物：`d:\LLSIFLocal\temp\netpatch\client_lan_<IP>.apk`

> 注意 `-BaseApk` 默认是 `temp\installed_base.apk`（含之前的 Lua 补丁，用来取 smali），
> 但它的 `AppAssets.zip` 里 `server_info.json` 曾被错误的 v3 覆盖过，解不开。
> 脚本会自动退回 `-ConfigApk`（默认 `LoveLive_9.7.1_patched.apk`）取干净配置。
> 换 IP 前如果发现解密报 `Unknown V3+ decryption method`，就是撞上了这个坑。


## 四、「下载 NaN%」和「无限重复下载」的真正根因

症状：客户端进不去游戏，停在下载界面，进度条显示 `NaN%`；服务端日志里
`POST /main.php/download/update` 一次一次地来，并反复下载同一个 `99_0_115.zip`。

关键日志：

```
[update] external="97.4.6" install="97.1.1" os="Android" pkgs=4410
```

两个版本号不一样：

| 字段 | 客户端从哪读 | 原值 |
|---|---|---|
| `external_version` | `AppAssets.zip/config/server_info.json` 的 `server_version` | 97.4.6（之前已改过） |
| `install_version` | `AppAssets.zip/config/package_info.json` 的 `server_version` | **97.1.1（没改）** |

只要 `external != install`，客户端就判定自己是「旧版本没装完」，于是**必进下载流程**去要
bootstrap 包。而服务端此时 `pkg_type=99` 的 bootstrap 包并不存在（或版本对不上），
`response_data` 于是为空：

- 返回空数组 → 客户端拿 `total=0` 做除法 → 显示 **NaN%**
- 服务端为了不让列表为空就「补一个包」→ 客户端下完再问 → 又问又补 → **无限重复下载**

所以前两次修服务端（`pad` / `padCooldown` / `nopad`）都只是在治症状。**真正的修法是把
客户端的两个 `server_version` 都对齐到服务端 `config.PackageVersion`**：对齐后客户端根本
不会进下载界面，`response_data` 空不空都无所谓。

代码层面：`internal/handler/download/update.go` 里**删掉了补包逻辑**，版本一致时就是干净的
空列表；只在 `external != PackageVersion`（真升级）时才下发 bootstrap 包 +
`static/Android/archives/99_0_115.zip`（server_info 覆盖包，内含与 `PackageVersion` 一致的配置）。

`99_0_115.zip` 现在是合法 v4，三个配置文件都在里面：

```
config/server_info.json    domain=http://192.168.0.106:8080  server_version=97.4.6
config/package_info.json   server_version=97.4.6
config/client_info.json    （原样）
```

`/static/Android/archives/*.zip` 请求**。正常进游戏应该是：

POST /main.php/lbonus/execute          ← 登录奖励，说明已经过标题画面
POST /main.php/api                     ← 主界面批量接口

## 六、踩过的坑（别再重复）

| 现象 | 原因 |
|---|---|
| 改完 server_info 就闪退 | 用 `-c`（v3）加密，客户端要 v4 → 必须 `-e -c4` |
| 改完还是连 127.0.0.1 | 只改了 server_info，没改 dex 里的常量（或反之） |
| 客户端报 `SocketTimeoutException ... /127.0.0.1 (port 8080)` | 这就是 localhost 直连失败，靠 `adb reverse` 才能通；要彻底解决必须按本文改两处 |
| `adb reverse` 老是丢 | 它是 adb 进程级状态，adb 重启/插拔就没了；服务端 App 现在每 5 秒会自动补，但这只是过渡方案 |
| 装完丢存档 | 用别的 keystore 签名会要求卸载重装；必须用同一个 `askey.keystore` |
| 服务端 404 `/resources/maintenace/update.php` | 该路由原先没注册，已补 `internal/handler/maintenance/update.go` |
| 服务端发的 `99_0_115.zip` 客户端解不开 | 里面是旧的 v3 文件，已重建为合法 v4（`server_version` 对齐 97.4.6） |
| 停在下载界面显示 `NaN%` / 无限重复下载 | `package_info.json` 的 `server_version` 没跟着 `server_info.json` 一起改，客户端认为自己是旧版本，必进下载流程；两个都要改成服务端 `config.PackageVersion` |
| 脚本报 `Unknown V3+ decryption method` | 取配置的来源 APK 里那份 `server_info.json` 曾被错误的 v3 覆盖；脚本会自动退回 `-ConfigApk`（原始 APK） |
| 脚本报了 `NativeCommandError` 就中断 | `$ErrorActionPreference=Stop` 会把外部程序的 stderr 当异常；脚本内部已用 `Invoke-Honoka` 包装 |
| 脚本中文乱码/解析失败 | `.ps1` 必须存成 **UTF-8 with BOM**，否则 PowerShell 按 ANSI 读，中文和 `$name.verify` 这类插值会解析崩 |
| 重启服务端后，游戏里所有功能都提示「正在维护」 | `startup` 每次启动都无条件把全员 `force_relogin` 置 1，中间件随后对所有非登录接口返回 404；已改成只有真的迁移过玩家档案才标记 |

## 七、地址会变的问题

PC 走 DHCP 时 IP 可能变（本项目就遇到过 `.107` → `.106`）。三种处理：

1. 路由器里给 PC 做 **DHCP 地址保留**（推荐，一劳永逸）
2. IP 变了就重跑一次 `patch_client_lan.ps1 -Ip <新IP>`
3. 服务端 App 的「总览 → 网络与端口」会显示本机 IP 和 cdn_server 是否一致，方便发现变化

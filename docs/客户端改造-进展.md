## 二、注入层入口（smali）

`com/sifpatch/Boot` 挂三处：

| 位置 | 调用 | 作用 |
|---|---|---|
| `GameEngineApplication.onCreate` | `Boot.onAppCreate` | 同步 server_info、首次清理会话、启动转发 |

## 四、账号层（M5）

### 服务端接口

| 接口 | 说明 |
|---|---|
| `GET /local/ping` | 健康检查：版本、DB 路径、账号数、磁盘余量 |
| `GET /local/accounts` | 账号列表：`user_id`/`phone`/`name`/`level`/`last_login_time`/`bound` |
| `POST /local/switch` | 手机号+密码校验，通过后登记切换目标 |
| `POST /local/unbind` | 清绑定，下次启动回原生登录页 |
| `GET /local/accounts/:id/backup` | 导出该账号全部行到 `assets/backups/<id>/<ts>.json` |
| `GET /local/accounts/:id/backups` | 列出备份（滚动保留 7 份） |
| `POST /local/accounts/:id/restore` | 用备份覆盖该账号；恢复前自动留底 |

`AutoBackup` 由 `loginauto` 调用，同一账号每天最多自动备份一次。

### 设备绑定（切号如何落到客户端）

表 `device_binding(device_id, user_id, bound_at)`，`/v1/account/loginauto` 改为**绑定优先**：

1. 若存在 `__pending__` 占位绑定（抽屉刚切号），**优先取它**，并把绑定提升为真实
   `device_id`、删除占位行 —— 否则精确绑定还指向旧账号，重启会回到旧号；
2. 否则按 `device_id` 精确查；
3. 都没命中时按 `autokey` 查 `users`，命中则顺手建立绑定。

抽屉拿不到 ghome SDK 生成的真实 `device_id`，所以 `/local/switch` 不传 `device_id`
时写 `__pending__`。

密码仍是唯一凭据（绑定只在「已验证」之后建立），不需要伪造盛趣登录 UI。

验证记录：

```
GET  /local/ping       -> {"ok":true,...,"user_count":4,"disk_free":361708941312}
GET  /local/accounts   -> 4 个账号，含 user_name / user_level / bound
POST /local/switch     -> 错密码 {"ok":false,"message":"密码有误"}
POST /local/switch     -> 对密码 -> user_id/autokey/ticket，accounts 里 bound=true
GET  /local/accounts/1792563557/backup  -> 559331 字节，含 user_pref + 3963 张卡
POST /local/accounts/1792563557/restore -> {"ok":true}，数据完好且自动留底
```

## 五、踩过的两个「黑屏 / 卡标题」坑（务必保留结论）

### 1. `AppAssets.zip` 里 `config/server_info.json` 的位置

`Boot.syncServerInfo` 用 `ZipInputStream` **顺序扫描** APK 内 `assets/AppAssets.zip`，
逐条 `getNextEntry()` 找 `config/server_info.json`。该文件原本排在第 **6420/8421** 条，
需要先解压 **64 MB** 才能找到，且 `AppAssets.zip` 在 APK 内还被二次压缩 ——
结果主线程在 `onCreate` 里被卡住上百秒，表现为**长时间纯黑屏**。

修法（已应用）：重打包时把 `config/server_info.json` 放到 zip **第一条**，
并把 `assets/AppAssets.zip` 加进 `apktool.yml` 的 `doNotCompress`。
用 `debuggerd -b <pid>` 抓主线程栈即可看到卡在 `Boot.syncServerInfo`。

### 2. 把手拖动改动会导致标题页不响应点击

v7 起把手改成 `TOP|RIGHT` + `topMargin` 持久化并加入纵向拖动，实测**进游戏后标题页
不响应点击**（`/v1/account/loginauto` 不再触发，只能停在标题）。回退到 v5 的
`CENTER_VERTICAL|RIGHT` + 「抬起即开面板」后恢复正常。

所以**把手位置持久化暂不做**，宁可要稳定。

### 3. 注入层会清掉自动登录凭据（一次）

`Boot.ensureFreshSession` 在首次运行（标记文件 `files/sif_session_cleared_v5` 不存在）时
会清空除 `sif*` 之外的所有 `shared_prefs`，其中包括 `klb.android.lovelivecn_preferences.xml`
里的 `gl_autokey`/`gl_userid`。清完后客户端会回到「点击画面」后要重新登录。

手工恢复：

```sh
D=/data/data/klb.android.lovelivecn/shared_prefs
cp /sdcard/prefs_boot.xml $D/klb.android.lovelivecn_preferences.xml
chown u0_a334:u0_a334 $D/klb.android.lovelivecn_preferences.xml
chmod 660 $D/klb.android.lovelivecn_preferences.xml
restorecon $D/klb.android.lovelivecn_preferences.xml
```

`temp/prefs_boot.xml` 即模板（含 `gl_autokey` / `gl_userid` / `gl_quicklogin_data`）。
